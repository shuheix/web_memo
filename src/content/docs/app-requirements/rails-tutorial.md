## このメモの狙い

教材を「手順」ではなく **機能の集合** として読み直し、別言語/フレームワークで再実装するときの仕様書にする。
1 アプリ = 1 md。対象は [Rails チュートリアル](https://railstutorial.jp/) のサンプルアプリ（`sample_app`）。

**全体像**: Twitter 風のミニ SNS を、静的ページ → ユーザー認証 → 投稿 → フォロー/フィード の順で段階的に作る。
これで **Web アプリの型（MVC・認証・CRUD・関連付け・メール・ファイルアップロード・TDD・デプロイ）はほぼ一周** できる。

## 章ごとの機能一覧

| 章 | 機能グループ | 主な機能 |
|---|---|---|
| 3〜5 | 静的ページ | Home / Help / About / Contact の表示、共通レイアウト（ナビ・フッター）、ページごとの動的タイトル |
| 6〜7 | ユーザー管理 | email / password で新規登録、バリデーション（存在性・長さ・フォーマット・一意性）、パスワード暗号化、Gravatar 画像、flash メッセージ |
| 8 | ログイン・基本 | ログイン / ログアウト、ログイン状態による画面表示の切替 |
| 9 | ログイン・発展 | remember me（ログイン状態の保持）、記憶有無をチェックボックスで選択 |
| 10 | 編集・一覧・削除 | プロフィール編集、未ログインのアクセス制限（認可）、本人以外の編集禁止、フレンドリーフォワーディング、ユーザー一覧（ページネーション）、管理者権限・管理者による削除 |
| 11 | アカウント有効化 | 有効化メール送信、メール内リンクからの有効化 |
| 12 | パスワード再設定 | 再設定メール送信、メール経由の再設定 |
| 13 | マイクロポスト（投稿） | 投稿の作成・削除、投稿バリデーション、プロフィールでの投稿一覧、画像添付（アップロード・検証・リサイズ） |
| 14 | フォロー・フィード | フォロー / 解除（Hotwire 対応）、フォロー中 / フォロワー一覧、フォロー数などの統計、フォロー中ユーザーの投稿フィード |

## 次に足すなら（チュートリアルで触れない/浅い技術を学べる機能）

チュートリアルを一周すると Web の型は揃う。次は **「その機能を作ると新しい技術が強制的に学べる」** ものを選ぶと効率が良い。

| 追加する機能 | 新しく学べること |
|---|---|
| リアルタイム通知 / DM（チャット） | Action Cable（WebSocket）。"サーバーから push する" 体験。フィードはリロード反映なので新鮮 |
| 重い処理の非同期化（メール・画像・集計） | Active Job + Solid Queue / Sidekiq。同期送信をジョブに逃がす設計 |
| ソーシャルログイン（Google / GitHub） | OAuth・外部 API 連携・omniauth。認証を他サービスに委譲する流れ |
| 課金・サブスク | Stripe 連携・Webhook 受信・外部サービスとの状態同期。Webhook は実務頻出だが未登場 |
| 全文検索 / 絞り込み検索 | LIKE を超えた検索（pg_search / Meilisearch）。N+1・インデックス・パフォーマンス |
| role/権限管理の本格化 | 認可ライブラリ（Pundit / CanCanCan）。admin フラグ手書きから宣言的ポリシーへ |
| API モード + 別フロント（React/Vue） | JSON API 設計・トークン認証（JWT）・CORS・SPA 分離 |
| 多言語対応（日/英切替） | i18n。地味だが実務で必須。後付けの難しさも学べる |

**方向性のおすすめ**: 一番「違う世界」を見たいなら **リアルタイム通知 / 非同期ジョブ**、実務で効くのは **ソーシャルログイン / 権限管理**。

## 他フレームワークで作るなら

- 認証: Rails の `has_secure_password` に相当するものを探す（[[spring-boot-for-rails-devs]] なら Spring Security）。
- Rails では「本体に入っている」機能（メール・画像・マイグレーション）が、他では依存追加になることが多い。この機能一覧がその差分を洗い出す土台になる。

## このメモの狙い

学習用アプリを「手順」ではなく **機能の集合** として棚卸しし、言語/フレームワークを問わず再実装するときの仕様書にする。1 アプリ = 1 md。

題材は **ユーザー認証つきのミニ SNS**（短文投稿＋フォロー）。この一式を作ると **Web アプリの型（MVC・認証・CRUD・関連付け・メール・ファイルアップロード・TDD・デプロイ）はほぼ一周** できる。

> 機能の洗い出しにあたっては [Rails チュートリアル](https://railstutorial.jp/) を参考にした。

**作る順序の目安**: 静的ページ → ユーザー認証 → 投稿 → フォロー/フィード。

---

## 機能一覧

### 静的ページ
- Home / Help / About / Contact の表示
- 共通レイアウト（ナビ・フッター）
- ページごとの動的タイトル

### ユーザー管理
- email / password で新規登録
    - バリデーション: 存在性 / 長さ / フォーマット / 一意性
    - パスワードは暗号化して保存
- プロフィール画像
- 登録成功時の flash メッセージ

### ログイン
- 基本
    - ログイン / ログアウト
    - ログイン状態による画面表示の切替
- 発展
    - remember me（ログイン状態の保持）
    - 記憶するかをチェックボックスで選択

### 編集・一覧・削除
- プロフィール編集
- アクセス制御（認可）
    - 未ログインのアクセス制限
    - 本人以外の編集禁止
    - フレンドリーフォワーディング（ログイン後に元のページへ戻る）
- ユーザー一覧（ページネーション）
- 管理者権限
    - 管理者によるユーザー削除

### アカウント有効化
- 有効化メール送信
- メール内リンクからの有効化

### パスワード再設定
- 再設定メール送信
- メール経由の再設定

### 投稿（マイクロポスト）
- 投稿の作成・削除
- 投稿バリデーション
- プロフィールでの投稿一覧
- 画像添付
    - アップロード / 検証 / リサイズ

### フォロー・フィード
- フォロー / フォロー解除
- フォロー中 / フォロワー一覧
- フォロー数などの統計
- フォロー中ユーザーの投稿フィード

## Advance（基本形の先で新しい技術を学べる機能）

上の一式で Web の型は揃う。次は **「その機能を作ると新しい技術が強制的に学べる」** ものを選ぶと効率が良い。

| 追加する機能 | 新しく学べること |
|---|---|
| リアルタイム通知 / DM（チャット） | WebSocket（Action Cable 等）。"サーバーから push する" 体験。基本のフィードはリロード反映なので新鮮 |
| 重い処理の非同期化（メール・画像・集計） | 非同期ジョブ（Sidekiq / Solid Queue 等）。同期送信をジョブに逃がす設計 |
| ソーシャルログイン（Google / GitHub） | OAuth・外部 API 連携。認証を他サービスに委譲する流れ |
| 課金・サブスク | Stripe 連携・Webhook 受信・外部サービスとの状態同期 |
| 全文検索 / 絞り込み検索 | LIKE を超えた検索（pg_search / Meilisearch 等）。N+1・インデックス・パフォーマンス |
| role/権限管理の本格化 | 認可ライブラリ（Pundit / CanCanCan 等）。手書きフラグから宣言的ポリシーへ |
| API モード + 別フロント（React/Vue） | JSON API 設計・トークン認証（JWT）・CORS・SPA 分離 |
| 多言語対応（日/英切替） | i18n。地味だが実務で必須。後付けの難しさも学べる |

**方向性のおすすめ**: 一番「違う世界」を見たいなら **リアルタイム通知 / 非同期ジョブ**、実務で効くのは **ソーシャルログイン / 権限管理**。

## フレームワークを変えて作るなら

- 認証・メール・画像・マイグレーションなどは、フレームワークによって「本体に入っている」か「依存を足す」かが分かれる。この機能一覧はその差分を洗い出す土台になる（例: [[spring-boot-for-rails-devs]]）。
